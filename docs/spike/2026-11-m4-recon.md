# Spike log: recon for M4 (course table + select screen), Nov 2026

How the arcade picks, loads and shows a course today, measured in MAME (read/write taps with PC on the course
variables, display-list and tile-RAM logs, snapshots) and read in the boot ROM (now correctly laid out, Phase 6).

## 1. Selection (boot ROM `0xfc26c5`)

- Wheel → `R10 = ([0x501060] + [0x50106c]) >> 1`; course `R11 = 0`, `+1` if `R10 > 0x1c`, `+1` if `R10 > 0x58`;
  `[0x501940] = R11` (menu index 0..2: Big Forest, Bay Bridge, Acropolis). Two thresholds, no scrolling.
- **Course table `0xfc35c7`, 24 bytes per course**, indexed by the menu index (`movea.b FC35C7[R11]` at `0xfc2708`
  and `0xfc28a0`):

  | +0 f32 | +4 f32 | +8 u32 | +0xc i32 | +0x10 i32 | +0x14 u32 |
  |---|---|---|---|---|---|
  | panel x (−151, 1, 153) | panel y (88) | select-panel tile map, window address (`0x1e0000`, `0x1e02b8`, `0x1e015c`) | −128 / 42 / 85 | 41 / 84 / 128 | **data index** (2, 0, 1) |

  `[0x501934] = entry+0x14` every frame of the select screen (`0xfc270f`). The +0xc/+0x10 pair looks like a
  cursor range (unverified).
- The selected panel's yellow frame is the only polygon object on the screen (display list: one object,
  `poly_adr 1208969`, `tex 276440`, size 5500, translated to the entry's (x, y)); everything else is tile art.

## 2. Select-screen art

- Bank 0 is mapped during attract and select (bank writes: frame 272 → 1, 616 → 0, 1602 → course bank).
  Bank 0 starts with an upload directory (`0x00100020, 0x0014a324, …`), like a course bank's graphics directory;
  the character data is copied into char RAM (`0x7e0000..`) at frame 616 by `0xffe59c` from window pages
  `0x100000..0x116a00` and `0x14a300..`.
- The three panel tile maps are read from bank 0 at window `0x1e0000..0x1e1800` (`0xff9461/0xff9484`) and
  written to tile RAM pages `0x701200..0x701300` (`0xff948a`) and `0x70c400..0x70c600` (`0xfc4076`); entry
  sizes (`0x15c`, `0x15c`, …) fit a ~16 × 19 tile map at 2 bytes per tile. Format still to decode (task).
- Program ROM `0x2e0600..0x2e0c00` is read by `0xff853c/0xff854c` during the build (font or layout data).

## 3. Course load (`0xfe415b` bank switch, `0xfe48ed` loader)

- Bank: `[0xe00004] = ((data_index + 1) << 4) | 1`. MAME maps bank `n` to region `0x1000000 + n × 0x100000`
  for `n` in 0..7; the `vr` set populates banks 0..3 only (bank 0 shared, 1 Bay Bridge, 2 Acropolis, 3 Big
  Forest). Stock MAME cannot load more ROM than the driver declares, so **new courses must live inside banks
  1–3's free space** (802 / 719 / 725 KB of 0xff; bank 0 has 52 KB).
- Loader `0xfe48ed` with `R10 = [0x501934]` (data index):
  - header at the **window base**: `[0x100004]` → segment entry 1 (`0x501950`), counts (`0x501954/8`);
    `[0x100008]` → collision map (`0x50196c`); `[0x10000c]` → surface table (`0x501970`); `[0x100010]` →
    pointer block + 8 (`0x501960`). These four absolute reads are the "header at bank +0" assumption.
  - per-course pointer tables indexed by `R10`: `0xfcd5b9 / 0xfcd5c5 / 0xfcd5d1` (three variants chosen by
    flags `0x40dc8c`, `0x501105`; the pointed table indexed by `[0x501110]` → `0x501968`), `0xfcf16d` →
    `0x50195c`, **`0xfe49a4` → tile table** (`0x2f1856, 0x2f1c56, 0x2f2056`), **`0xfda543` → entity spawn list** (Phase 7 correction: not a HUD map; the minimap is an entity in it)
    (`0xfda54f, 0xfdb39f, 0xfdb90b`).
  - then TGP `0x0680, R10` (collision slot = data index; the slot table has 16 entries, 3 used).
- In-race users of the data index: `0xfedd89` (hot: `0xfcf1a9[idx]` pointer table used with the lap quad —
  checkpoints/sectors?), `0xfe8e88` pit entry (`0xfe8e0c`, Phase 6), `0xfeac09` (`0xfeac1b[idx]` → entity
  `+0x18` object list), and course-specific branches `cmp.b #0/#1, [0x501934]` at `0xfe8bdb`, `0xff4743`,
  `0xfc0bf2` (Bay Bridge / Acropolis specials). `[0x501936]` is a separate flag (manual gearbox?).

## 4. Free space for code and tables

Boot ROM: 13 KB at `0xfdc845`. Program ROM (executable, `0x200000..`): 92 KB at `0x278d70`, 57 KB at
`0x2b1842`. Data ROM: see §3.

## 5. What M4 has to change (input to the plan)

1. A ten-entry **course directory** (new, in free program ROM): data bank, header base (window address),
   TGP slot (3..9 are free), template data index for the in-race per-course tables, tile table address, HUD
   map pointer, pit-entry quad, select panel (tile map + name), difficulty label.
2. Selection: menu index 0..9 at `0x501940`, wheel scrolls a row of ten (replaces the two thresholds); the
   24-byte course table → the directory (two reference sites).
3. Loader: bank from the directory; header reads relative to the directory's header base instead of
   `0x100004..0x100010`; tile table, spawn list and TGP slot from the directory; `[0x501934]` = the template index
   so the untouched in-race tables keep working (Bay Bridge's template has no pit lane).
4. Select panels for the seven courses (the HUD minimap turned out to be drawn from the road lines; the spawn list at `0xfda54f` holds entities).
5. Course banks for new courses built at a free offset of banks 1–3 (`bank.build_bank` relocates the lines
   already; the header and the collision/surface/segment tables need the same freedom).
